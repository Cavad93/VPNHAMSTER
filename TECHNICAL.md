# Технические детали VPNHAMSTER

## Архитектура

### Общая схема

```
┌─────────────────┐                    ┌──────────────────┐
│   Mac Client    │                    │ Windows Server   │
│                 │                    │   (Астана)       │
│  ┌───────────┐  │                    │  ┌────────────┐  │
│  │Application│  │                    │  │ Internet   │  │
│  └─────┬─────┘  │                    │  │ Gateway    │  │
│        │        │                    │  └─────▲──────┘  │
│        ▼        │                    │        │         │
│  ┌───────────┐  │                    │  ┌─────┴──────┐  │
│  │   TUN0    │  │                    │  │   TUN0     │  │
│  │ 10.8.0.2  │  │                    │  │  10.8.0.1  │  │
│  └─────┬─────┘  │                    │  └─────▲──────┘  │
│        │        │   Encrypted TCP    │        │         │
│  ┌─────▼─────┐  │ ════════════════►  │  ┌─────┴──────┐  │
│  │  Client   │  │      8888          │  │   Server   │  │
│  │  Process  │  │ ◄════════════════  │  │  Process   │  │
│  └───────────┘  │                    │  └────────────┘  │
└─────────────────┘                    └──────────────────┘
```

### Поток данных

1. **Приложение → TUN**: Приложение отправляет IP пакет
2. **TUN → Client**: Client читает пакет из TUN интерфейса
3. **Client Encryption**: Пакет шифруется ChaCha20-Poly1305
4. **Client → Server**: Зашифрованный пакет отправляется по TCP
5. **Server Decryption**: Сервер расшифровывает пакет
6. **Server → Internet**: Расшифрованный IP пакет отправляется в интернет
7. **Обратный путь**: Ответ идет тем же путем в обратном направлении

## Протокол

### Уровень фреймирования

Каждое сообщение обрамляется длиной:

```
┌─────────────┬──────────────────────────┐
│   Length    │     Encrypted Data       │
│  (4 bytes)  │      (N bytes)           │
│  Big-endian │                          │
└─────────────┴──────────────────────────┘
```

### Формат зашифрованных данных

После расшифровки:

```
┌──────┬────────┬─────────────────────────┐
│ Type │ Length │       Payload           │
│(1 B) │ (4 B)  │      (N bytes)          │
└──────┴────────┴─────────────────────────┘
```

### Типы сообщений

| Type | Name       | Direction | Payload              | Description                    |
|------|------------|-----------|----------------------|--------------------------------|
| 1    | HELLO      | C→S       | Version string       | Начальное приветствие          |
| 2    | HELLO_ACK  | S→C       | "OK" or error        | Подтверждение соединения       |
| 3    | DATA       | C↔S       | Raw IP packet        | IP пакет                       |
| 4    | KEEPALIVE  | C↔S       | Empty                | Поддержание соединения         |
| 5    | DISCONNECT | C↔S       | Empty                | Запрос на закрытие соединения  |

## Шифрование

### ChaCha20-Poly1305

**Параметры:**
- Алгоритм: ChaCha20-Poly1305 AEAD
- Размер ключа: 256 бит (32 байта)
- Размер nonce: 96 бит (12 байт)
- Размер тега: 128 бит (16 байт)

**Формат зашифрованного пакета:**

```
┌─────────┬─────────────┬────────┐
│  Nonce  │ Ciphertext  │  Tag   │
│ (12 B)  │   (N B)     │ (16 B) │
└─────────┴─────────────┴────────┘
```

**Процесс шифрования:**

1. Генерация случайного nonce (12 байт)
2. Шифрование plaintext с помощью ChaCha20
3. Вычисление Poly1305 MAC для аутентификации
4. Concatenation: nonce || ciphertext || tag

**Безопасность:**

- ✅ Защита конфиденциальности (ChaCha20)
- ✅ Аутентификация (Poly1305)
- ✅ Защита от replay атак (случайный nonce)
- ✅ Защита от MITM (аутентифицированное шифрование)

### Почему ChaCha20-Poly1305?

1. **Скорость**: Быстрее AES на процессорах без AES-NI
2. **Безопасность**: Современный криптографический стандарт (RFC 8439)
3. **Мобильность**: Отличная производительность на ARM (Mac M1/M2)
4. **Простота**: Устойчив к timing attacks

## TUN/TAP интерфейсы

### Что такое TUN?

TUN (network TUNnel) - виртуальный сетевой интерфейс на уровне IP (L3).

**Отличие от TAP:**
- TUN работает с IP пакетами (Layer 3)
- TAP работает с Ethernet фреймами (Layer 2)

Для VPN нам нужен TUN, так как мы туннелируем IP трафик.

### Создание TUN на Mac

```python
tun = pytun.TunTapDevice(flags=pytun.IFF_TUN | pytun.IFF_NO_PI)
tun.addr = '10.8.0.2'        # IP адрес интерфейса
tun.netmask = '255.255.255.0'  # Маска подсети
tun.dstaddr = '10.8.0.1'     # Адрес назначения (gateway)
tun.mtu = 1500               # Maximum Transmission Unit
tun.up()                     # Активировать интерфейс
```

### Создание TUN на Windows

Windows требует специальных драйверов:
- TAP-Windows (от OpenVPN)
- Wintun (современная альтернатива)

```python
tun = pytun.TunTapDevice(flags=pytun.IFF_TUN | pytun.IFF_NO_PI)
tun.addr = '10.8.0.1'
tun.netmask = '255.255.255.0'
tun.mtu = 1500
tun.up()
```

### Чтение/запись TUN

**Чтение** (получение исходящих пакетов):

```python
packet = tun.read(tun.mtu)  # Читаем IP пакет (до 1500 байт)
```

**Запись** (отправка входящих пакетов):

```python
tun.write(packet)  # Записываем IP пакет в интерфейс
```

## Маршрутизация

### Mac (клиент)

**До подключения:**

```
default via 192.168.1.1 dev en0
```

**После подключения:**

```
195.49.210.123 via 192.168.1.1 dev en0  # Маршрут к серверу
default via 10.8.0.1 dev utun3           # Весь остальной трафик
```

**Команды:**

```bash
# Добавить маршрут к серверу через старый gateway
route add -host 195.49.210.123 192.168.1.1

# Добавить default route через туннель
route add -net 0.0.0.0 10.8.0.1
```

### Windows (сервер)

**IP Forwarding:**

```powershell
# Включить IP forwarding
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters" `
  -Name "IPEnableRouter" -Value 1

# Настроить NAT
netsh routing ip nat install
netsh routing ip nat add interface "tun0" private
```

## Производительность

### Overhead анализ

**Без туннеля:**

```
Application → IP → Ethernet → Wire
```

**С туннелем:**

```
Application → IP → TUN → Encryption → TCP → IP → Ethernet → Wire
                        (+28 bytes)  (+20)  (+20)   (+14)
                        Total overhead: ~82 bytes per packet
```

**Практический overhead:**
- Шифрование: ~12 байт nonce + 16 байт tag = 28 байт
- TCP header: 20 байт
- IP header: 20 байт
- Ethernet: 14 байт
- Фрейминг: 4 байта (length)

**Итого**: ~86 байт overhead на каждый IP пакет

### MTU расчет

```
Internet MTU: 1500
- IP header: 20
- TCP header: 20
- Encryption: 28
- Framing: 4
= 1428 bytes (рекомендуемый MTU для TUN)
```

Но мы используем 1500 для простоты, полагаясь на TCP фрагментацию.

### Латентность

| Компонент          | Задержка    |
|--------------------|-------------|
| TUN read/write     | < 1 ms      |
| Encryption         | < 1 ms      |
| TCP передача       | RTT к серверу|
| Decryption         | < 1 ms      |
| Routing            | < 1 ms      |

**Общая дополнительная задержка**: 2-5 ms + RTT к серверу

### Пропускная способность

ChaCha20 на современных CPU:
- **Mac M1**: ~5 GB/s на ядро
- **Intel i7**: ~2 GB/s на ядро

Узкое место - **канал до сервера**, не шифрование.

## Безопасность

### Анализ трафика

**Что видит провайдер:**

```
Source: 178.176.XX.XX (ваш IP в РФ)
Destination: 195.49.210.123 (сервер в Астане)
Protocol: TCP
Port: 8888
Payload: Encrypted binary data
```

**Что НЕ видит провайдер:**
- ❌ Куда вы на самом деле заходите
- ❌ Что вы смотрите
- ❌ Какие сайты посещаете
- ❌ Содержимое трафика

### DPI обход

**Deep Packet Inspection (DPI)** пытается обнаружить VPN по:
1. Сигнатурам протоколов (OpenVPN, WireGuard)
2. Паттернам зашифрованного трафика
3. Размерам пакетов

**Наша защита:**
- ✅ Нет известных сигнатур (собственный протокол)
- ✅ ChaCha20 дает случайный вывод (неотличимо от random)
- ✅ TCP туннель (похож на обычное соединение)
- ✅ Можно использовать порт 443 (выглядит как HTTPS)

2. **Множественные серверы**:

## Ограничения и известные проблемы

### Текущие ограничения

1. **Single-threaded**: Один поток обработки (можно улучшить)
2. **No reconnection**: При обрыве нужно перезапускать (можно добавить)
3. **No compression**: Трафик не сжимается (можно добавить LZ4)
4. **Basic routing**: Простая маршрутизация (можно улучшить)
